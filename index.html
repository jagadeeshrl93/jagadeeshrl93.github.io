How I think

Engineering principles I ship by.

Measure before you optimize

Every architectural decision in my RAG system was validated with RAGAS scores before and after. I instrument, measure, and then decide.

Own every layer you ship

I built the chunker from scratch because I wanted to understand the tradeoffs before tuning them. You can't debug a black box during an incident.

Infrastructure first

Most AI engineers build models that are hard to run in production. I start from containerized, observable, and cost-aware infrastructure.

Reliability over cleverness

The system that stays up at 3am beats the clever one that occasionally fails. I favor patterns that are simple, proven, and operable.

Security by default

Running Ollama locally keeps sensitive runbooks and infrastructure context inside the network unless there is explicit justification.

Hybrid beats pure

Vector search finds meaning. BM25 catches exact terms. The best systems combine approaches intelligently instead of forcing one pattern.

Case Study

RAG Cloud Docs — deep dive.

A production-grade RAG system built from scratch. No framework magic — every layer understood and owned.

The problem

On-call engineers spent 20+ minutes searching through runbooks during incidents. Keyword search returned too many irrelevant results.

The approach

Build a RAG system that answers in natural language, cites its source, and runs locally with Ollama so data stays inside the network.

The result

Sub-second query latency, 0.929 faithfulness, 1.000 context recall, and 0.945 context precision across domain Q&A pairs.

Architecture
DocumentsPDF · MD · HTML
Chunker512 tokens
EmbeddingMiniLM
RetrievalVector + BM25
AnswerOllama + citations

Why hybrid retrieval?

Vector search understands meaning, while BM25 catches exact flags, error codes, and version numbers. RRF combines both.

Why custom chunking?

Chunk size directly affects answer quality. 512 tokens with 50-token overlap gave the best balance of context and precision.

Why Ollama?

Zero API cost, local inference, and no sensitive infrastructure documents leaving the network.

Why RAGAS?

Evaluation made every tuning decision measurable instead of subjective.
